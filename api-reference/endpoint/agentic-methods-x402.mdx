## Overview

The Agentic API is the private-key based surface for Brickken agentic methods. It covers ERC-8004 agent identity, reputation, and agent-owned ERC-20 token operations.

Use this surface when you do not want to use a Brickken API key. Your private key stays local and is used to sign:

- the x402 USDC payment authorization; and
- the prepared blockchain transaction before `send-transactions`.

<Warning>
Never send a private key to the Brickken API. Private-key signing belongs in your client, the [Brickken CLI](/cli/introduction), or an MCP session you control.
</Warning>

| Environment | Base URL |

## Authentication Flow

For x402, omit `x-api-key`.

1. Call a semantic facade such as `POST /x402/agent/register`, or call `POST /prepare-transactions` with an eligible `method`.
2. If payment is required, the API returns `402 Payment Required` with a `PAYMENT-REQUIRED` response header.
3. Decode and sign the x402 payment locally with the payer private key.
4. Retry the same request with `X-Payment`.
5. Sign the returned prepared blockchain transaction locally.
6. Submit it with `POST /send-transactions`, following the same x402 retry flow if required.

```http
X-Payment: BASE64_ENCODED_X402_PAYMENT_PAYLOAD
```

The API returns `PAYMENT-RESPONSE` after settlement. The payment rail uses USDC with EIP-3009 authorization. Always read the chain, asset, amount, recipient, and timeout from `PAYMENT-REQUIRED`; do not hardcode them client-side.

## Discovery

```http
GET /.well-known/x402
GET /openapi.json
```

Production (`https://api.brickken.com`) is the public x402scan target. Sandbox exposes the same discovery routes for QA.

## Prepare and Send

The semantic `/x402/...` routes prepare unsigned transactions. They do not submit transactions on-chain by themselves.

```bash
curl --request POST 'https://api.sandbox.brickken.com/x402/agent/register' \
  --header 'Content-Type: application/json' \
  --data '{
    "chainId": "11155111",
    "signerAddress": "0xYourWallet",
    "name": "Research Agent",
    "description": "Autonomous research agent",
    "image": "https://example.com/agent.png",
    "services": [
      {
        "name": "A2A",
        "endpoint": "https://agent.example/.well-known/agent-card.json",
        "version": "0.3.0"
      }
    ],
    "aiModelName": "Research Model",
    "aiModelProvider": "OpenAI",
    "x402Support": true,
    "active": true
  }'
```

After signing the returned transaction:

```bash
curl --request POST 'https://api.sandbox.brickken.com/send-transactions' \
  --header 'Content-Type: application/json' \
  --header 'X-Payment: BASE64_ENCODED_X402_PAYMENT_PAYLOAD' \
  --data '{
    "txId": "0xPreparedTransactionId",
    "signedTransactions": ["0xSignedRawTransaction"]
  }'
```

`send-transactions` x402 batches must contain only x402-eligible prepared transactions, and all transactions in the batch must be on the same chain.

## Common Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `chainId` | string | Yes | Target chain ID. Decimal and hex values are accepted. |
| `method` | string | Yes for `/prepare-transactions`; no for `/x402/...` facades | One of the eligible method names. Facades derive it from the path. |
| `signerAddress` | string | Yes | Wallet that signs the prepared blockchain transaction. |
| `gasLimit` | string or number | No | Optional explicit gas limit. |
| `nonce` | number | No | Optional explicit nonce when managing nonces manually. |
| `privateRpcUrl` | string | No | Optional RPC override. |

## Response Shape

The prepare response includes `txId`, `transactions`, and optional `info`. For `agentRegister`, save `info.agentUuid` for later `set-uri` and `set-metadata` calls.

<Warning>
x402 payments and on-chain transactions are non-refundable. Confirm chain, signer, recipient, token address, and expected USDC price before signing. See [Pricing](/api-reference/endpoint/agentic-pricing) for the published mainnet table.
</Warning>
