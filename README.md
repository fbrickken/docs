# Brickken Documentation

Source for [docs.brickken.com](https://docs.brickken.com), built with [Mintlify](https://mintlify.com).

## Local development

```bash
npm install
npm run dev
```

Serves the site at `http://localhost:3000`. The CLI package is `mint` — if you have the deprecated `mintlify` package installed globally, remove it first with `npm uninstall -g mintlify`.

Check every internal link before opening a PR:

```bash
npm run check
```

Redirects are applied by the hosting layer, not by `mint dev`. Verify them on the PR preview deployment.

## Structure

| Path | Contents |
| --- | --- |
| `docs.json` | Navigation, tabs, redirects, global anchors, theme |
| `get-started/` | Onboarding: capabilities, surface choice, authentication, API key request, quickstart |
| `api-reference/` | Dapp API and Agentic API pages, plus the OpenAPI spec |
| `api-reference/openapi.json` | **Generated artifact** — see below |
| `cli/`, `mcp/`, `skill/` | Client documentation |
| `snippets/` | Shared MDX fragments and the API key request form component |
| `downloads/` | Postman collection, environments, and the packaged Skill |

Note that `api-reference/endpoint/` physically holds the Agentic API and RAMS pages too. The directory layout does not mirror the tab structure in `docs.json`, and that is deliberate — moving the files would change public URLs for no reader-visible gain.

## The OpenAPI spec

`api-reference/openapi.json` is generated by the backend and served live at `GET /openapi.json`. Do not hand-edit it beyond metadata: the next regeneration overwrites local changes. Fixes to paths, schemas, or security schemes belong in `dApp-backend`.

## Snippets

Shared content lives in `snippets/` and is imported after the frontmatter:

```mdx
import Environments from '/snippets/environments.mdx';

<Environments />
```

Snippets cannot import other snippets. The API key request form is a React component in `snippets/api-key-request-form.jsx` — Mintlify pre-injects the React hooks and forbids npm imports, so it uses browser built-ins only.

## Publishing

The Mintlify GitHub App deploys the default branch automatically. A merge to `main` publishes the whole diff at once, including redirects and deletions, so verify on the preview deployment before merging.
