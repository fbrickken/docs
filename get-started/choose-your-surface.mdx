The REST API, the SDK, the CLI, the MCP server, and the Skill all talk to the same backend at `api.brickken.com`. They differ in who is driving and which credential they carry.

## Start from what you already have

| You have | Use | Because |
| --- | --- | --- |
| An API key and a TypeScript codebase | **SDK** | Typed client for the whole platform, running in your process |
| An API key and any other stack | **REST API** | Plain HTTP reaches everything |
| A funded wallet and no API key | **SDK**, **Agentic API**, or **CLI** | Pay per call with x402; no account needed |
| An MCP-capable AI agent | **MCP** | One hosted endpoint, 62 tools, credentials set per session |
| A terminal and an agentic workflow | **CLI** | `npm i -g brickken-cli`, then one command per operation |
| An AI coding agent, any of the above | **Skill** | Teaches the agent when to use which surface |

## What each surface can reach

| | REST | SDK | MCP | CLI | Skill |
| --- | :---: | :---: | :---: | :---: | :---: |
| Dapp API writes | Yes | Yes | Yes | **No** | Guides the agent |
| Dapp API reads | Yes | Yes | Yes | **No** | Guides the agent |
| KYC link creation | Yes | Yes | Yes | Yes | Guides the agent |
| Agent getters | Yes | Yes | Yes | Yes | Guides the agent |
| Agentic writes (ERC-8004, agent tokens) | Yes | Yes | Yes | Yes | Guides the agent |
| RAMS writes | Yes | Yes | Yes | Yes | Guides the agent |
| RAMS reads | Yes | Yes | Yes | Yes | Guides the agent |
| Accepts an API key | Yes | Yes | Yes | KYC and supported reads | — |
| Pays with x402 | Yes | Yes | Yes | Yes | — |
| Where it runs | Your code | Your code | Hosted by Brickken | Your machine | Your agent |

<Warning>
**The CLI cannot call the general legacy Dapp API.** KYC link creation is the explicit exception. It has no commands or method mappers for tokenization, STO, or their read methods. `brickken tx prepare --method newTokenization` forwards the method name, but the backend answers `API key is required for this method`.

For Dapp API work, use the **SDK** if you write TypeScript, **MCP** if an agent is driving, or plain **HTTP** otherwise.
</Warning>

## SDK or MCP for the Dapp API?

Both reach the full Dapp API with nothing but an API key. The difference is who is holding the credential:

- **SDK** — your code holds the key, and every call is typed and testable. Illegal credential combinations fail locally, before a request leaves your process.
- **MCP** — a hosted endpoint holds nothing; each session supplies its own credentials, and an AI agent picks the tools. Right when the driver is an agent rather than a program you wrote.

## Same backend, same rules

Whichever surface you pick, the mechanics are identical: writes are **prepared** into unsigned transactions, **signed**, then **sent**; preparing a relayed agentic operation is free and only the send costs anything; and your private key never leaves your machine.

The surface changes the ergonomics, not the semantics — you can prepare with the CLI and send with curl.
